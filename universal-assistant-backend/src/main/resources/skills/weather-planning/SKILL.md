# 天气与行程规划

1. 从当前问题和最近对话中提取每个地点及对应日期。
2. 多地点或多日期必须拆成独立天气查询，不能把整句话当作地点。
3. 优先使用 `get_weather`，服务不可用或目标日期不支持时再请求 `web_search`。
4. 对每个地点和日期分别说明天气、温度、降雨或其他关键风险。
5. 用户要求优化行程时，根据天气结果给出具体调整，不能只说“我来查询”。
6. 无法获得某一地点的数据时明确标注缺失，不使用其他地点的数据代替。
